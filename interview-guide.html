HTMLDocuments, scripts, and language2
  1. What’s the difference between async and defer attributes used in a <script> tag?
    Suggested answer

    Both download an external script while HTML parsing continues. async executes as soon as its download finishes, so execution order is not guaranteed and it may interrupt parsing. defer waits until parsing is complete, preserves document order, and runs before DOMContentLoaded. I use defer for scripts that depend on the DOM or each other, and async for independent scripts such as analytics.

  2. How do you serve a page with content in multiple languages?
    Suggested answer

    I store interface text in locale files instead of hard-coding it, then select the correct translations using an internationalization library or server-side locale logic. Each page should set the correct lang attribute, use UTF-8, provide an explicit language switcher, and expose localized URLs with hreflang when pages are indexed. I also account for plural rules, dates, currencies, and right-to-left layouts rather than translating words only.

CSSLayout, selectors, and responsive design9
  1. Explain your understanding of the box model.
    Suggested answer

    Every element is a rectangular box made of content, padding, border, and margin. With the default content-box, a declared width applies only to the content, so padding and borders increase the rendered size. With box-sizing: border-box, the declared width includes content, padding, and border, which usually makes layouts easier to size.

  2. What’s the difference between a relative, fixed, absolute, and statically positioned element?
    Suggested answer

    static is the normal document flow. relative keeps its original space but can be offset and becomes a containing block for positioned descendants. absolute leaves normal flow and is positioned relative to its nearest positioned ancestor. fixed also leaves normal flow but is normally positioned relative to the viewport, so it stays in place while scrolling.

  3. What’s the difference between inline and inline-block?
    Suggested answer

    Both can sit within a line instead of starting a new row. A normal inline element flows with text and generally ignores explicit width and height; vertical margins also do not affect surrounding lines in the same way. An inline-block element stays inline externally but behaves like a box internally, so width, height, padding, and margins can be controlled.

  4. What is CSS selector specificity, and how does it work?
    Suggested answer

    Specificity is the browser’s scoring system for choosing between competing declarations. Inline styles outrank IDs, IDs outrank classes, attributes, and pseudo-classes, and those outrank element selectors and pseudo-elements. If specificity is equal, the later declaration wins. I keep selectors shallow and avoid !important except for deliberate utility or override cases.

  5. What are functions and mixins?
    Suggested answer

    CSS functions accept values and calculate or transform a result, such as calc(), min(), clamp(), and var(). A mixin is a reusable group of declarations, commonly provided by preprocessors such as Sass with @mixin and @include. Traditional mixins are not part of broadly supported plain CSS, so I also use custom properties, utility classes, and component styles for reuse.

  6. Have you used Flexbox or CSS Grid before? What did you think?
    Suggested answer

    Yes. I use both because they remove many manual positioning hacks and make responsive alignment more predictable. Flexbox is especially convenient for navbars, toolbars, and rows of controls, while Grid is excellent for page structure and card layouts. I choose based on the layout relationship instead of treating one as a replacement for the other.

  7. What are the differences between Flexbox and CSS Grid?
    Suggested answer

    Flexbox is mainly one-dimensional: it lays items out along a row or a column and is content-driven. Grid is two-dimensional: it controls rows and columns together and is more layout-driven. They work well together—for example, Grid can define the page or card columns while Flexbox aligns controls inside each card.

  8. How do you implement mobile-specific layouts?
    Suggested answer

    I start with a usable mobile layout, use flexible widths and responsive units, then add media or container queries when the content needs more space. I change layout rather than merely shrinking it—for example, stacking columns, simplifying navigation, keeping touch targets large, and preventing horizontal overflow. I test with real content, keyboard input, and several viewport sizes.

  9. How do you decide which responsive breakpoint to use?
    Suggested answer

    I choose breakpoints where the actual content or layout begins to fail, not from a list of specific device models. I resize the layout, identify the point where text, controls, or spacing become uncomfortable, and add the smallest query that resolves it. This keeps the design resilient to new screen sizes.

JavaScriptLanguage fundamentals and async behavior8
  1. Explain how this works in JavaScript.
    Suggested answer

    For a regular function, this is determined by how the function is called: as an object method, with new, with call/apply/bind, or as a plain function. Arrow functions do not create their own this; they capture it lexically from the surrounding scope. That is why extracting a method or changing its call site can change its this value.

  2. What is a closure?
    Suggested answer

    A closure is a function together with access to the lexical variables that existed where it was created, even after the outer function has finished. Closures are useful for private state, callbacks, and function factories. For example, a counter function can remember its own count between calls without using a global variable.

  3. What is hoisting?
    Suggested answer

    Hoisting describes how declarations are processed before execution. Function declarations can be called before their source line. var is initialized to undefined, while let and const exist in a temporal dead zone until their declaration is evaluated, so accessing them early throws an error. I still declare values before use for clarity.

  4. What is JSX?
    Suggested answer

    JSX is a syntax extension commonly used with React that lets us describe UI with HTML-like markup inside JavaScript. It is transformed into JavaScript element-creation calls, so it is not HTML and can embed expressions with braces. JSX also uses JavaScript-friendly names such as className and requires a single returned parent or fragment.

  5. What is the difference between == and ===?
    Suggested answer

    == performs loose equality and may convert operands before comparing them, which can produce surprising results such as 0 == false. === performs strict equality without type coercion, so both type and value must match. I use === by default and only use loose equality when its conversion behavior is intentional.

  6. What is a ternary expression?
    Suggested answer

    The conditional or ternary operator is an expression with three parts: condition ? valueIfTrue : valueIfFalse. It is useful for short value selection, including conditional JSX. If the logic has multiple branches or side effects, I prefer an if statement because it is easier to read.

  7. What is a Promise?
    Suggested answer

    A Promise represents the eventual result of an asynchronous operation. It starts pending and then becomes fulfilled with a value or rejected with an error. I can consume it with .then()/.catch() or with async/await, and I handle rejection rather than assuming the operation succeeds.

  8. What is a callback?
    Suggested answer

    A callback is a function passed to another function so it can be called later or for each item. Event handlers and array methods such as map use callbacks. Asynchronous callbacks can become deeply nested, so Promises and async/await often provide clearer control flow, but callbacks remain a fundamental JavaScript pattern.

ReactComponents, data flow, and rendering6
  1. What is state? What are props? What is the difference between them?
    Suggested answer

    Props are read-only inputs passed from a parent to a component. State is data owned by a component whose update can trigger a re-render. A component should never mutate either directly: the parent supplies new props, while state is updated through React’s state setter or reducer. I keep state as close as possible to the components that need it.

  2. What are two ways to create components in React?
    Suggested answer

    React components can be written as functions or classes. Modern React code normally uses function components with Hooks because they are concise and compose reusable behavior well. Class components use lifecycle methods and this, and they are still important when maintaining older applications or using class-based error boundaries.

  3. How does the Virtual DOM work?
    Suggested answer

    When props or state change, React creates a new description of the UI and reconciles it with the previous one. Using element types and keys, it determines which real DOM updates are required, then commits those changes efficiently. The Virtual DOM is not automatically faster than every manual update; its main value is a predictable declarative programming model and batched reconciliation.

  4. What is prop drilling, and how can you avoid it?
    Suggested answer

    Prop drilling is passing data through intermediate components that do not need it just so a deep descendant can receive it. I first consider component composition or moving state closer to where it is used. For truly shared values I may use Context, a state-management library, or a server-state library, but I avoid adding global state for ordinary local data.

  5. How can you style your React components?
    Suggested answer

    Options include regular stylesheets, CSS Modules, utility classes such as Tailwind, CSS-in-JS libraries, inline styles, and component libraries. I choose based on the project’s conventions, theming needs, runtime cost, and how much style isolation is required. Regardless of the tool, I keep styles accessible, responsive, and maintainable.

  6. Why are keys important?
    Suggested answer

    Keys give list items stable identities across renders, helping React match old and new elements during reconciliation. A good key is unique among siblings and stable for the lifetime of the item, usually a database ID. Array indexes can cause incorrect state or unnecessary updates when items are inserted, removed, or reordered.

Node.js + databasesRuntime, packages, and data stores3
  1. What is the event loop?
    Suggested answer

    JavaScript executes on a call stack, while Node delegates many I/O operations to the operating system or its worker pool. When work completes, callbacks are queued, and the event loop processes them through its phases when the stack is available; Promise microtasks run at defined points with high priority. This model enables high I/O concurrency, but CPU-heavy synchronous work can still block every request.

  2. What’s the purpose of package-lock.json?
    Suggested answer

    It records the exact resolved dependency tree, including transitive package versions and integrity hashes. Committing it makes installs more reproducible across developers and CI and lets npm ci perform a clean deterministic install. package.json describes the allowed dependency ranges; the lockfile records what was actually resolved.

  3. What is the difference between SQL and NoSQL databases?
    Suggested answer

    SQL databases use relational tables, schemas, joins, and SQL, and they are strong when relationships and transactional consistency matter. NoSQL is an umbrella term for document, key-value, wide-column, and graph databases, often with more flexible data models or specialized scaling patterns. I choose based on access patterns, relationships, consistency needs, and operations—not because one category is universally better.

Core web conceptsArchitecture, inclusion, and performance6
  1. What is object-oriented programming?
    Suggested answer

    Object-oriented programming organizes software around objects that combine data and behavior. Common ideas are encapsulation, abstraction, inheritance, and polymorphism. In JavaScript I can use classes and prototypes, but I also favor composition when it creates simpler, less tightly coupled code.

  2. What is a RESTful API?
    Suggested answer

    A RESTful API models data as resources identified by URLs and uses HTTP semantics consistently: methods such as GET, POST, PATCH, and DELETE, meaningful status codes, headers, and representations such as JSON. Requests should be stateless, so each contains the context needed to process it. For example, GET /tasks/42 retrieves one task and PATCH /tasks/42 changes part of it.

  3. What is web accessibility?
    Suggested answer

    Web accessibility means people with visual, auditory, motor, cognitive, or other disabilities can perceive and operate the product. I start with semantic HTML, labels, keyboard support, visible focus, sufficient contrast, meaningful alternatives, and clear errors, then test with keyboard and assistive technology. Accessibility is part of design and engineering quality, not a final checklist.

  4. How do you pay attention to a site’s performance?
    Suggested answer

    I define a performance budget, measure both lab and real-user behavior, and focus on user-visible metrics such as loading, responsiveness, and layout stability. I profile before optimizing so I can find the actual bottleneck. I also monitor after release because device speed, network conditions, and real data can differ from local development.

  5. What performance techniques do you use?
    Suggested answer

    I compress and correctly size images, lazy-load noncritical media, minimize and split JavaScript, defer nonessential work, cache static assets, reduce request count and payload size, optimize fonts, and avoid expensive rendering. On the server I inspect queries, use pagination and caching where appropriate, and stream or pre-render content when it improves the experience.

  6. How would you measure whether a performance improvement worked?
    Suggested answer

    I capture a baseline, change one meaningful variable, and compare the same scenario and device conditions. I use browser profiling and tools such as Lighthouse for diagnosis, then verify field metrics and product outcomes after release. I look for improvements in both technical metrics and user impact without causing regressions elsewhere.

General engineering questions

8 questions
01

What is SDLC?

Explain the Software Development Life Cycle and how work moves from planning through maintenance.

View suggested answer

SDLC is the structured process used to plan, build, release, and maintain software. It normally includes requirements, planning and design, implementation, testing, deployment, and maintenance. The phases may be sequential or iterative; in Agile teams we move through them in smaller cycles and use feedback from each release to guide the next one.

02

What is Git?

Describe version control and the branching strategies you are familiar with.

View suggested answer

Git is a distributed version-control system that records code history and lets developers work safely in parallel. I use branches for isolated changes, make focused commits, review diffs, and merge through pull requests. I’m familiar with feature branches and trunk-based development; Git Flow can suit release-heavy products, while short-lived branches are usually simpler for continuous delivery.

03

How do you ensure software quality?

Discuss code review, manual testing, unit tests, integration tests, and end-to-end automation.

View suggested answer

I build quality into the workflow: clarify acceptance criteria, keep changes small, use linting and type checks, review code, and test at the right levels. Unit tests cover isolated logic, integration tests cover boundaries such as APIs and databases, and a smaller number of end-to-end tests protect critical user flows. I also do exploratory and accessibility testing because automation cannot catch every usability problem.

04

How do you continuously learn?

Explain how you choose topics, practice, apply feedback, and measure improvement.

View suggested answer

I connect learning to a real goal instead of collecting tutorials. I read primary documentation, build a small example, apply the idea in a project, and explain it in my own words. I keep notes on gaps found during reviews or interviews and revisit them through coding exercises, then measure progress by whether I can solve and explain the problem without a guide.

05

Which standards do you apply?

Talk about readability, consistency, accessibility, security, testing, and documentation.

View suggested answer

I optimize first for understandable and maintainable code: clear names, small focused units, consistent formatting, explicit error handling, and minimal duplication. I follow the project’s conventions, validate input at trust boundaries, use semantic and accessible UI patterns, and add tests around important behavior. I document decisions and non-obvious trade-offs rather than restating the code.

06

What excites you about coding?

Connect your motivation to the kind of problems and users you enjoy serving.

View suggested answer

I enjoy turning an unclear problem into something people can use. Coding combines logical problem-solving with continuous feedback: I can form a hypothesis, build a small solution, test it, and improve it. Frontend work especially interests me because technical decisions immediately affect usability, accessibility, and how confident a user feels.

Customize this answer

I considered [options] and chose [solution] because [trade-off]. After adding [test or monitoring], the result was [measurable outcome]. I learned [specific lesson].”

08

What is your web page workflow?

Walk through requirements, structure, implementation, testing, review, and delivery.

View suggested answer

I first clarify the user goal, content, states, constraints, and acceptance criteria. I outline semantic HTML and the responsive layout, then build the smallest usable version before adding interactions. I test keyboard use, accessibility, different viewport sizes, loading and error states, performance, and browser behavior, then review the diff, get feedback, deploy, and monitor the result.

  1. 01

    Describe the most exciting project you have worked on and the biggest challenge you faced.

    View sample STAR answer

    Situation: I built a learning dashboard where users could read concepts and run JavaScript exercises in the browser. Task: I needed to make code execution useful without allowing an infinite loop to freeze the page. Result: The interface stayed responsive even for broken solutions, and I learned to treat user-provided code as an isolation and resource-control problem.

  2. 02

    Give an example of a time when you set a goal and were able to meet or achieve it.

    View sample STAR answer

    Situation: I wanted to strengthen my JavaScript fundamentals before building a full-stack project. Task: My goal was to finish a structured set of lessons and tested exercises within four weeks. Action: I divided the material into daily topics, tracked completion, practiced without copying solutions, and reviewed mistakes every weekend. Result: I completed the plan on time and could explain and test the core concepts more confidently. The key was using small measurable milestones instead of one broad goal.

  3. 03

    Give an example of a time when you set a goal and were not able to achieve it. What did you learn?

    View sample STAR answer

    Situation: I planned to finish an entire project in one week while learning several new tools at the same time. Task: I wanted to deliver every planned feature by the deadline. Action: I worked through the list but realized late that I had not estimated integration and testing work. Result: I delivered the core flow but missed secondary features. I learned to separate must-haves from optional scope, identify unknowns early, add testing time, and communicate risk before the deadline.

  4. 04

    You’re working on a project with a tight deadline, but you are stuck because you do not know how to solve a bug. How will you handle the situation?

    View suggested answer

    I would first make the bug reproducible, reduce it to the smallest failing case, and inspect logs, inputs, recent changes, and documentation. I would time-box independent investigation so I do not hide the risk. If I remain stuck, I would ask a teammate with a concise summary of what I expected, what happened, and what I already tried. I would communicate the deadline impact early, propose a safe workaround or scope reduction if needed, and add a regression test once the cause is fixed.

  5. 05

    Tell us about a time you wrote code that you later realized could be significantly improved.

    View sample STAR answer

    Situation: I initially built a form with validation, API calls, and UI updates inside one large event handler. Task: When new fields were added, changes became risky and tests were difficult to write. Action: I separated pure validation, request handling, and rendering into focused functions, defined consistent error results, and added unit tests before changing behavior. Result: The code became easier to test and extend. I learned to refactor around clear responsibilities, but only after protecting existing behavior with tests.

Challenge 02

FizzBuzz

Loop from 1 to 100. Output “fizz” for multiples of 3, “buzz” for multiples of 5, and “fizzbuzz” for multiples of both.

1, 2, "fizz", 4, "buzz", …, "fizzbuzz"
View one solution 
for (let number = 1; number <= 100; number += 1) {
  if (number % 15 === 0) console.log("fizzbuzz");
  else if (number % 3 === 0) console.log("fizz");
  else if (number % 5 === 0) console.log("buzz");
  else console.log(number);
}
